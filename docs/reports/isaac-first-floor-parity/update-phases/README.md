# Native update-phase investigation

Target: installed Repentance 1.7.9b, executable SHA-256 pinned in [manifest.json](manifest.json). **Dispatch and bounded player physics are verified; full actor/live timing remains unaccepted. The v18 runtime correction uses a separate 60 Hz player clock. Universal dodge, its movement boost and immunity remain enabled.**

The original outer loop calls the manager update at `88bdf5`, then rendering at `88bdfa`. Its pacing calculation and wait loop use the double at `b6a658`, exactly `1/60` second. This establishes the native target interval; it does not measure actual elapsed time under load or establish every actor's update frequency. [main_loop.asm](main_loop.asm) and [clock-constants.csv](clock-constants.csv) preserve these inputs. The clock wrapper can use QueryPerformanceCounter or a fallback; neither operating-system clock is executed by this fixture.

The manager's gameplay switch selects state **2**. Its phase counter is at `manager+4a264`; the interpolation control byte is at `manager+29e73`. The script executes the original branch at `8b02aa` with six supplied counter values, both control values and both restoration flags: **24 cases**, recording both actors in [manager-routing.csv](manager-routing.csv). Even phases dispatch `Game::Update` at `6cdcf0`. Before that dispatch, an actor with byte `16d` set has its position restored from saved coordinates `29c/2a0` into `294/298`, and its restoration flag cleared. Odd phases dispatch `6d0400` only when the interpolation control is enabled. The actual called game updates are intercepted in these routing probes.

Another **12 executed cases** check the earlier manager entry: an odd phase with interpolation disabled increments the phase and returns before the main manager work. See [odd-skip.csv](odd-skip.csv). Option loading at87fdfe..87fe25 references `EnableInterpolation` with a true fallback; complete initialization/default/profile behavior and all pause/transition paths remain unaccepted.

Four additional probes execute original `6d0400`, with actual player and ordinary NPC vtable addresses and a supplied two-entity room. In the ordinary state it sets player flag `0x4000`, calls the player's full update slot (`74b8d0`), calls player collision (`683850`, argument zero), clears the flag and calls the NPC's interpolation slot (`6a8a40`). A supplied pause counter or either tested transition state suppresses that ordinary dispatch. [alternate-dispatch.csv](alternate-dispatch.csv) records the calls and flags. **Player update, collision and NPC interpolation endpoints immediately return in these probes; their behavior is not executed or accepted.** The native pause queries and alternate traversal instructions execute without replacement.

The main Room update calls entity manager `413480` at `7c059e`. Its active-entity gate at `413714..41376f` dispatches both actual Player and NPC update vtables. **48 executed gate cases** vary actor type, active state, the manager mode argument, `FLAG_RENDER_FLOOR`/`FLAG_NO_REMOVE_ON_TEX_RENDER` and `FLAG_TRANSITION_UPDATE`. The endpoint bodies remain intercepted; see [main-entity-gate.csv](main-entity-gate.csv). These cases verify the selected gate, not every pass in the entire manager.

When interpolation is disabled, `413ce8..413e4a` supplies the extra flagged player update and collision pass inside that same main entity update. **Eight executed cases** cover interpolation enablement, the manager mode argument and transition eligibility; see [extra-player-pass.csv](extra-player-pass.csv). Together with alternate dispatch, these establish two ordinary player update calls per main world update in either interpolation mode. Disabling interpolation changes the scheduling of the extra player call rather than removing it. NPC AI stays on the main phase. The target loop therefore implies 60 player calls and 30 ordinary NPC calls per second; real elapsed-time delivery remains unmeasured.

The preserved installed `resources/scripts/enums.lua` defines `FLAG_INTERPOLATION_UPDATE = 1<<14` and describes it as the odd update at 60 fps. That agrees with the recorded bit and dispatch. It does not establish whether a particular movement, shooting or hurt-counter branch executes on both phases. Separate windows preserve the player movement call and hurt decrement for follow-up. The game's ordinary frame counter increments inside `Game::Update`, so that counter alone cannot calibrate all player operations.

The executable import table also corrects a research label: IAT address `a064c0` is **WINMM.dll `timeGetTime`**, not `GetTickCount`. The Duke fixture's hosted profiling endpoint is unchanged (returns zero); its manifest now uses the correct API name. No native game clock was replaced in that AI capture.
